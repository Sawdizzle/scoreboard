Help & setup

🚀 Quick start
  1. + New Game — pick the sport, then the scorebug style.
  2. Open the game. 📋 Game setup at the top walks you through teams, lineups, defense, and the overlay link.
  3. 🔗 Overlay link & practice → Copy. That URL is what goes into OBS.
  4. Add it in OBS as a Browser source (settings below).
  5. Score from this pad — the overlay updates instantly. Keep the pad open on your phone or iPad; it holds the screen awake while a game is open.

Practice first: ▶ Demo Mode in the same panel plays a fake game so you can check the look with nobody watching.

⚙️ Recommended OBS settings

Settings → Video

Base & Output resolution1920×1080 both
FPS30. Baseball is mostly still between pitches — 60 roughly doubles encoding and rendering work for very little visible gain, and on a fanless laptop that's the difference between coasting and throttling.

Settings → Output (Advanced mode) → Streaming

EncoderHardware. “Apple VT H.264 Hardware Encoder” on a Mac, NVENC on an Nvidia PC. Never x264 — software encoding is pure CPU and heat.
Rate control / bitrateCBR, 6000 kbps for 1080p30 (YouTube's range is 4500–9000).
Keyframe interval2 seconds
AudioAAC, 128–160 kbps, 48 kHz

Settings → Output → Recording

Encoder“Same as stream”. This is the important one. Any other setting makes OBS encode the whole game a second time, continuously, for the entire broadcast. Same-as-stream reuses frames it's already producing and costs almost nothing.
FormatHybrid MP4 (or MKV) — a crash or dead battery won't corrupt the file the way plain MP4 does.

Settings → Output → Replay Buffer

Maximum replay time90 seconds. Auto-clips wait up to 60s after a walk-off before saving, and the buffer has to still reach back past the pitch. It holds encoded video in RAM — about 70 MB at 6000 kbps.

And on the Scorebug browser source: 1920×1080, FPS 30 (match your video FPS — a browser source at 60 doubles the cost of every animation), “Shutdown source when not visible” unchecked.

⚡ What costs performance

Roughly in order, largest first:

  1. Every additional camera. This is bigger than everything else on this list combined. A capture device decodes continuously whether or not its scene is on air — two cameras means two pipelines running for the whole game. Switching between them is free; having them isn't.
  2. A software encoder (x264) instead of your machine's hardware encoder.
  3. A separate recording encoder — encodes the game twice. See “Same as stream” above.
  4. 60 FPS instead of 30, on either the video output or the browser source.
  5. Full-screen takeover cards, and only while one is on screen. They animate continuously, so the overlay repaints every frame instead of sitting still. They're up during breaks, never during live play.
  6. Everything else this app does — clips, scene switches, stream control, status updates — is idle until you press something. It's a WebSocket carrying a few bytes per event, with no polling anywhere.

If a laptop is struggling with two cameras: tick “Deactivate when not showing” on the capture devices. Only the on-air camera then decodes — but the camera has to wake up on each switch, so cuts get a visible beat. Fast cuts or lower load; pick one.

Heat matters more than CPU on a fanless laptop. Two hours of streaming plus recording outdoors will throttle a machine sitting in the sun or in a bag long before it runs out of processing power. Keep it shaded, raised for airflow, and plugged in.

Check it yourself rather than trusting any of this: View → Docks → Stats, and watch three numbers during a game — OBS's CPU usage, frames missed due to rendering lag (this catches the overlay), and frames dropped due to encoding lag (this catches a double encode or too-high bitrate). Put a takeover card up for a minute with Stats open; rendering lag should stay at zero.

🔐 How much OBS access to give

One dropdown decides how much of OBS this app may touch: the overlay source's Page permissions. Every setting below is a fine way to run the app — pick the lowest one that covers what you actually want.

Page permissionsWhat you get
No access
the default		Scorebug, all cards and takeovers, moments, sound, camera-independent everything. The whole overlay works.
Basic…plus 🎞️ Clip and auto-clip.
Advanced…plus 🎥 Cameras (scene switching) and starting/stopping the replay buffer.
Full…plus 📡 Go live, end stream, and record.

The pad adapts on its own: anything above your level is greyed out with a needs advanced tag on the panel, and the note under it tells you which setting to raise. Nothing breaks and nothing nags — a locked feature is a choice you haven't made, not an error.

Changing the dropdown reloads the source, which is also how the pad finds out. If the pad still shows the old level, right-click the source → Refresh.

🖥️ OBS browser source settings

Sources → + → Browser, name it “Scorebug”.

  • URL — the link you copied from the game.
  • Width 1920 · Height 1080, FPS 30 or 60.
  • Leave Custom CSS alone — the page is already transparent.
  • Uncheck “Shutdown source when not visible” — keeps the live connection alive between scenes.
  • Page permissions — see “How much OBS access to give” above. Leave it at No access if you only want the scorebug and cards.
  • Check “Control audio via OBS” so overlay sounds reach the stream. In the Audio Mixer, set that source's monitoring to “Monitor and Output” to also hear it in your headphones.

Size and place the bug from 🎨 Appearance (3×3 position grid + scale) instead of resizing the source — the source should stay 1920×1080.

📡 Running the stream from the pad

With the overlay source set to Page permissions: “Full access to OBS”, 📡 Stream & record on the game screen runs the broadcast:

  • 🔴 Go Live / ⏹ End Stream — starts and stops the stream itself.
  • ⏺ Record / ⏹ Stop Rec — the local recording.
  • 🎞️ Buffer On / Off — the replay buffer, so you can start it from the field when the pad warns it isn't running. This one only needs “Advanced”.

Each button shows what OBS is actually doing, not what you last pressed — OBS reports every one of these changes, so starting a recording at the machine lights the button here too.

Stopping takes two taps. The first arms the button (“Tap again to end”) and it disarms itself after five seconds, so a pocket tap can't end your broadcast. Starting is a single tap.

🎥 Switching cameras

OBS can't show or hide one source from a web page, so a camera change is a scene change. Build it like this:

  1. One scene per camera — “Center Field”, “Backstop”, and so on, each with just that camera in it.
  2. Add the scorebug to the second scene with + → Browser → “Add Existing” → Scorebug. Do not create a second browser source.
  3. On that source, set Page permissions: “Advanced access to OBS” — a step above what clips need.

Then 🎥 Cameras on the game screen lists your scenes, highlights the one on air, and cuts to whichever you tap using your configured transition. Switch at the OBS machine instead and the pad follows along.

“Add Existing” matters. A duplicate browser source is a second overlay: doubled audio, and one Clip press saving two files. If you ever do need a second copy, add &obs=0 to its URL so only one of them talks to OBS.

🎞️ Instant replay clips

One-time OBS setup:

  • Settings → Output → enable the Replay Buffer and set it to 90 seconds.
  • Settings → General → Output → “Automatically start replay buffer when streaming”.
  • The buffer has to be started, not just enabled — the pad warns you if it isn't.

Then, during the game:

  • 🎞️ Clip saves the buffer right now. The line under the button reports what actually happened — clip saved, buffer not running, or permissions too low.
  • Auto-clip big plays clips home runs, walk-offs, double plays, big plays, touchdowns, and goals on its own.
  • Auto-clips wait out the celebration before saving (40s on a home run), because the buffer only records backward — that's how the clip gets the swing and the mob at the plate. Tap Clip during the countdown to take it early.
  • Clips land in the same folder as your OBS recordings.
🎬 Cards & full-screen takeovers

Everything under 🎬 Broadcast cards stays up until you clear it with ✕ Clear card.

  • Corner cards float over the video: Matchup, Final, Due Up, Sponsor, and live Batting order / Defense.
  • Full-screen takeovers hide the scorebug and cover the camera: 🕐 Starting Soon (countdown to first pitch — set First pitch in Setup), 🔁 Mid-Inning (the scoreboard during the change, and it stays live), and 🏁 Final (full).
  • Your camera keeps running behind a takeover, so crowd noise carries through and you never have to switch scenes in OBS.
⚾ Running the game
  • The main pad is game flow — balls, strikes, fouls, outs, runs, hits, bases, End ½ Inning. Runs, strikeouts, and walks fire their own stinger.
  • ↶ Undo reverses the last action.
  • ✏️ Manual adjust is for corrections when the board drifts from the field.
  • Moments fire the big animations with sound. Rally and 🎺 Charge! are there for atmosphere.
  • Save teams with rosters under 👥 Teams & lineups and reuse them next game.
🔧 Troubleshooting
  • Overlay looks stale after an update — right-click the source → Refresh. OBS caches page files hard.
  • Only part of the bug shows — the source has to be 1920×1080.
  • No overlay sound on the stream — check “Control audio via OBS” on the source.
  • “Replay buffer isn't running” — start it in the main OBS window, below Start Streaming.
  • Nothing is updating — watch the dot in the game header: green is synced, red is reconnecting. It heals itself when the network comes back, and the overlay never blanks out in the meantime.
